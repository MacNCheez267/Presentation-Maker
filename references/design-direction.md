# Design Direction

Use this guide for Create mode to synthesize a story and visual direction before authoring in the selected platform or file workflow. For concise briefs and default selection across independent design dimensions, first follow [Design System Generation](design-system-generation.md). Search only relevant reference material; do not force a product taxonomy onto a general presentation.

## Consult relevant design references

Start with the brief, audience, outcome, delivery context, supplied sources, and any brand assets. Then find a fitting match in each relevant domain:

1. **Content or product category and pattern.** For a product- or service-focused deck, use [Reasoning Rules](reasoning-rules.md) to match the product type first, then apply its category-specific story and visual cues. For lessons, research, reports, strategy, training, and other general presentations, use [Presentation Structures](presentation-structures/index.md) instead. For example, a biology lesson about prokaryotic and eukaryotic cells is an education lesson, not an online-learning product.
2. **Style.** Use [Product Styles](product-styles/index.md) for product or service decks and [Style Recommendations](style-recommendations/index.md) for translating the request and audience into a visual direction. Choose one dominant style and at most one restrained supporting influence.
3. **Color palette.** Search [Color Palettes](color-palettes/index.md) for the closest useful category match. Define primary, secondary, emphasis, background, and text roles. Preserve supplied brand values and check contrast against actual slide content.
4. **Typography.** Search [Font and Typography Pairings](font-and-typography-pairings/index.md) for a candidate heading/body pairing and a readable hierarchy. Treat named fonts as candidates until the selected platform confirms availability or the generated file can be inspected.
5. **Effects and UX.** Consult [UX Guidelines](design-guideline.md), plus [Chart Types](chart-types/index.md) when charts or data displays are used. Choose only effects that support the story, comprehension, or requested mood.

Use the closest category only when it genuinely fits. If the references do not contain a suitable match, adapt a neighboring recommendation based on audience and purpose, and identify the adaptation briefly instead of implying it is an exact match. Do not add taxonomy entries or invent brand rules to fill a gap.

When a real-world design example would materially improve a style decision or the user requests inspiration, review a small number of relevant examples online where search is available. Adapt observable qualities such as hierarchy, palette, image treatment, or spacing; do not copy a layout or identity. Cite a specific example when it materially supports the recommendation. Do not browse merely to fill the four design domains when the supplied brief and references are sufficient.

## Apply decision priorities

Resolve conflicts in this order:

1. The user's explicit requirements, supplied brand assets, and source material.
2. The audience, intended outcome, delivery format, readability, accessibility, and factual accuracy.
3. The correct story pattern and category rules: product type first for product or service decks; presentation purpose for general decks.
4. A coherent style recommendation that fits those requirements.
5. Palette and typography choices made independently to support the brief, while staying readable and available. Style does not lock either choice.
6. Optional effects, which are subordinate to content, brand, and legibility.

A visual trend or category convention is a starting point, not a reason to override the brief, mislead the audience, or reduce readability.

## Provide the design summary in the final report

For a created presentation, include a concise **Design Summary** in the final report. Cover these fields, combining related details where that keeps the report brief:

- **Style:** the dominant visual direction and any restrained supporting influence.
- **Color palette:** the color roles and values used, or supplied brand values.
- **Typography:** confirmed heading/body fonts when available, otherwise clearly labeled candidates, and the main hierarchy.
- **Layout approach:** the composition pattern and how it supports the story or slide sequence.
- **Imagery and design elements:** notable photos, diagrams, illustration, texture, transitions, or animation; “none” is a valid choice.
- **Anti-patterns to avoid:** a short, deck-specific list of choices that would undermine this brief, audience, or style.
- **Pre-delivery checklist:** status each key check as passed, needs attention, or unverified. Include story and coverage, source accuracy, readability/accessibility, visual consistency, chart accuracy where applicable, and preview/tool limitations.

Keep the report concise and describe what the finished presentation actually uses. Do not label a font, effect, chart, color, image treatment, or layout as applied unless the selected platform result or readable preview confirms it. If a detail cannot be confirmed from the available preview, label it unverified rather than implying it was applied.
