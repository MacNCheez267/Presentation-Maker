# Presentation Maker

Create, template, edit, or review presentations using the platform and capabilities available in the current environment. This skill is platform-neutral: follow the user's requested platform when available, otherwise select a suitable available workflow and explain material limits. Do not claim work is complete unless the tool or output confirms it.

## How to use this skill

Invoke `$presentation-maker` with a topic, brief, source material, existing presentation, or design request. State a preferred platform, audience, purpose, length, style, or source requirements when they matter. You can also ask for a review without edits. If details are missing, the skill will use sensible defaults for reversible choices and ask only when the gap could materially change the content or result.

## Choose the requested mode

- **Create:** make a new presentation from a brief or source material.
- **Template:** create from a named or linked reusable brand template or existing presentation.
- **Edit:** change an existing presentation within the requested scope.
- **Review:** inspect an existing presentation and report findings without changing it.

Infer the mode when the request makes it clear. Do not ask the user to select a mode unnecessarily. For Template, Edit, and Review, identify the exact source presentation before acting; resolve ambiguous matches with a concise choice question.

## Core workflow

1. Identify the mode, scope, requested platform, and essential inputs. Ask only about missing details that could materially change the result; otherwise use reversible defaults and state consequential assumptions.
2. Select a suitable available presentation tool or file workflow. Honor an explicit platform preference. Inspect the current tool descriptions and follow their limits, approval requirements, and continuation instructions. If the requested platform or capability is unavailable, explain that and offer a supported alternative when it preserves the user's intent.
3. Plan the presentation's story and gather supplied or verified content. Use [Presentation Structures](references/presentation-structures/index.md) for general decks; use [Reasoning Rules](references/reasoning-rules.md) only for product- or service-focused walkthroughs. Follow [Research and Sourcing](references/research-and-sourcing.md) when claims need external verification.
4. For Create mode, adapt [Design System Generation](references/design-system-generation.md) to the brief. Select story structure, visual style, color palette, typography, chart types, and effects as separate but compatible decisions. Consult only relevant references from the guide below.
5. Create, edit, or review within the requested scope. Protect existing source designs, use a copy when appropriate, and follow any tool-required review or approval before committing changes. Do not publish, share, or change access unless requested.
6. Inspect the available preview or readable content. Check factual support, story, layout, readability, accessibility, and charts where relevant. Report only what the tool or preview confirms, and identify material limitations.
7. For Create mode, deliver the confirmed presentation link or file when available, a concise content summary, and a concise post-completion design summary covering the style, color palette, typography, layout approach, and notable imagery or design elements. Report applied details only when confirmed by the tool or preview, and identify unverified details. Include the relevant design direction and pre-delivery checks.

## Boundaries

Honor explicit content, brand, accessibility, and design requirements over generic recommendations. Treat reference guidance as decision support, not permission to add content, features, or external actions the user did not request. Never bypass account restrictions or tool safeguards. Do not invent facts, figures, quotations, citations, brand assets, or tool results.
